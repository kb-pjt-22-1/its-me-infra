목 카드사 고객(kb_card_mock.mock_customers) 테스트용 원본 신원 정보
=================================================================
ci_hash = SHA-256(UTF-8(이름 + 생년월일(YYYYMMDD) + 전화번호))
Sha256Util.hash / SignupIdentityServiceImpl.buildCiHash와 동일한 공식.

ci_hash는 해시라서 역산이 안 되므로, mock_customers.ci_hash 값만 봐서는
원본 이름/생년월일/전화번호를 알 수 없다. 회원가입 1단계
(POST /api/auth/signup/identity)에서 실제로 입력해볼 값이 필요해서 여기에 남겨둔다.

(테스트용) dev-login.enabled가 켜진 환경(로컬 등)에서는 아래 목록에 없는 임의의
이름/생년월일/전화번호를 넣어도 회원가입이 막히지 않는다 - Mock Server가 등록된
고객을 못 찾으면 SignupIdentityServiceImpl이 그 자리에서 Mock Server에 새 고객+
무작위 카드를 만들어달라고 요청해서 등록/카드 자동연동 흐름을 이어간다
(KbCardClient.registerCustomer, MockCardServiceImpl.registerCustomer 참고). 아래
목록은 그래도 "특정 카드 구성으로 고정해서 테스트하고 싶을 때" 쓰면 된다.

회원가입 테스트 예시 (박종현)
-----------------------------
POST /api/auth/signup/identity
{ "name": "박종현", "birthDate": "19990404", "phoneNumber": "01044444444" }
-> devVerificationCode를 응답에서 그대로 받아서(DEV_LOGIN_ENABLED=true인 로컬 한정)

POST /api/auth/signup/identity/confirm
{ "phoneNumber": "01044444444", "code": "<devVerificationCode>" }
-> verificationToken 응답

POST /api/auth/signup
{ "loginId": "...", "password": "...", "pin": "......", "verificationToken": "<위 토큰>" }

주의: 이 파일과 mysql/init/04_mock_seed.sql의 ci_hash 값이 실제 실행 중인
mysql 컨테이너 볼륨에 반영되려면, 볼륨을 새로 만들거나(docker compose down -v)
kb_card_mock.mock_customers를 직접 UPDATE해야 한다 - init 스크립트는 볼륨을
처음 만들 때 한 번만 실행된다.
